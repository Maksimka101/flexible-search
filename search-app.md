# Поиск с плагинами — заметки

Продолжение `self-modifying-apps.md` (полигон 2: лаунчер + поиск).

# Часть 1. Решения

Здесь только то, чего нет в коде: принципы, отказы и планы. Принятое
и сделанное живёт в коде и KDoc.

## Продукт
- Android-приложение поиска, весь UI на Compose.
- Основа — layout Pixel Search (скриншот
  `DCIM/Screenshots/Screenshot_20261018_113340_Pixel Search.jpg`).
- Каждая мельчайшая часть изменяема и дополняема, и UI, и логика.
  Всё построено на базовых компонентах.
- Плагины загружаются через DexClassLoader. Внешние ставятся APK,
  встроенные — в APK хоста.

## Принципы
- Тонкий core. Изменения на уровне данных (JSON-оверлеи, порядок
  плагинов) делаются плагинами, а не в core. Исключение — выключение
  плагинов и экран настроек: они в core, иначе выключенное не включить.
- Никакого UI-фреймворка поверх Compose: ни своего дерева layout,
  ни своих токенов, ни своего UI-кита. Плагин подменяет любой
  компонент через `style` / `override`.
- Названия читаемые: `Middleware`, а не `Mw`.
- Core не смешивает и не ранжирует результаты разных плагинов: что
  релевантно, решает плагин.
- Обёрток над библиотеками нет: в `PluginScope` только то, где нужен
  хост. Версии общих библиотек — часть контракта с плагинами.
- Виджеты главного экрана: виджет ядра — в core; у встроенного плагина
  свой `AppWidgetProvider` в его пакете (receiver — в манифесте app), у
  внешнего — в его APK. Не через `PluginScope`; в поиск — `SearchLinks`.
  Кнопки в виджете поиска ядра — через `PluginScope.homeScreenButton`:
  RemoteViews собирает core, тап открывает окно и выполняет `Action`.

## Не делаем (пока)
- Виджеты: смахивание, кэш в core (кэширует плагин), состояние «нужно
  разрешение» в core (плагин рисует сам), pager (можно через
  `override(Results)`).
- Общая история нажатий в core: плагин помнит свои сам.
- Порядок плагинов, трогающих один компонент, — пока любой.
- Изоляция ошибок плагинов.
- Правка префиксов пользователем при конфликтах.
- Своя схема цветов из обоев: Material You берёт системную палитру,
  даже выбранную вручную.

## Запланировано
- Fuzzy: лимит разрыва между совпавшими символами (`te` не должен
  находить `boarding pass TIV-BEG.pdf`).
- Опечатки: второй проход через `LevenshteinDistance` (commons-text),
  если fuzzy ничего не нашёл. Будет много нерелевантного — откатить.
- Frecency в `AppsPlugin` (история уже в `prefs`), не в core.
- Props и Style пока `data class` (удобный `copy`). Новое поле ломает
  собранные плагины — их отсечёт версия API в манифесте, пересобрать.
  Перед чужими плагинами или когда API устоится — ABI-стабильные
  классы (Poko + `copy { }`), без параметров по умолчанию в API (см.
  ресерч, ABI).
- Enter без результатов в «Искать в…»: цель выбирается в настройках
  плагина (Claude и т. п.), пока — браузер по умолчанию.

## Открытые вопросы
- Подсказка команд: по `cal` показывать «calc — Calculator», Tab/Enter
  дописывает префикс. Делаем, продумать.
- Экран настроек приложения, куда плагины добавляют свои пункты.
- Как устроена логика: middleware-цепочки, `Item`, ранжирование.
- Детали загрузки через DexClassLoader: R8, доставка, подписи (см.
  ресерч ниже).

# Часть 2. Ресерч (кэш)

Источник — знания модели и рассуждения, на устройстве не проверено.
Перед опорой на пункт стоит перепроверить.

## Layout Pixel Search (по скриншоту)
1. Сверху строка: лого слева, поле, кнопка фильтров справа.
2. Середина пустая, видны обои: окно поверх обоев с затемнением.
3. Результаты прижаты к низу, к клавиатуре (`reverseLayout`).
4. Ряд из 5 приложений с подписями. Первое подсвечено — цель Enter.
5. Ряд «искать в…»: круглая кнопка веб-поиска + иконки
   (браузер, Maps, Play).

## DexClassLoader
- Формат плагина: обычный APK из модуля `com.android.application`.
  Точка входа и версия API — в `<meta-data>` манифеста.
- Читать через `getPackageArchiveInfo(path,
  GET_META_DATA or GET_SIGNING_CERTIFICATES)`: versionCode,
  точка входа и подпись одним вызовом.
- Android 14+: файл с dex должен быть read-only
  (`file.setReadOnly()`), иначе SecurityException.
- Копировать в internal storage:
  `filesDir/plugins/<id>/<versionCode>.apk`, для каждой версии новый
  файл. Из внешнего хранилища не грузить.
- `DexClassLoader(path, null, null, hostClassLoader)`, parent-first:
  Compose, Kotlin, coroutines и API плагин получает от хоста.
- В плагине API, Compose, stdlib, coroutines, OkHttp и
  kotlinx.serialization — `compileOnly`.
  Свои зависимости плагин вшивает в себя; у каждого плагина свой
  загрузчик, поэтому конфликтов нет, пока эти типы не ходят через API.
- Версии Kotlin/Compose у плагина и хоста одни (общий version
  catalog). При загрузке проверять версию API из manifest.
- ABI: в публичном API без `data class` и параметров по умолчанию —
  новое поле ломает собранные плагины. Проверка:
  `binary-compatibility-validator`.
- Выгрузка: убрать из реестра всё, что зарегистрировал плагин,
  `onUnload`, сменить `key(generation)` вокруг корня UI. Классы
  уйдут вместе с загрузчиком при GC. Горячая замена = выгрузка +
  загрузка с нового пути.
- Ресурсы: проще Compose без Android-ресурсов (`ImageVector`, байты).
  Если понадобятся — `getResourcesForApplication` с подставленными
  `sourceDir` / `publicSourceDir`.
- Нативные библиотеки (`librarySearchPath`) пока не нужны.
- Манифест плагина (`<queries>`, разрешения, компоненты) не действует:
  код работает под UID хоста. Видимость приложений — `QUERY_ALL_PACKAGES`
  хоста.
- Первый запуск dex медленнее (интерпретатор/JIT). Встроенные плагины
  компилировать в APK, внешние грузить в фоне.

## Изоляция ошибок
- В Compose нет error boundaries, исключение в composition роняет
  процесс.
- Маркер «гружу X» перед `install`, снять после. Остался при старте →
  отключить X.
- Пакет плагина = его id. В `UncaughtExceptionHandler` по кадрам
  стека найти плагин, отключить, перезапуститься (safe mode).
- Логика: каждый middleware в try/catch, при ошибке вызвать `next`
  с тем же входом и пометить плагин.

## Доставка плагинов
- `adb push` в `/sdcard/Android/data/<pkg>/files/inbox/` под
  временным именем, затем `mv`. Хост ловит `FileObserver` + проверка
  на resume.
- Termux не может писать в `Android/data` (scoped storage). Для
  сборки внутри приложения проще встроенный proot: APK сразу в своём
  `filesDir`.
- Безопасность: плагин работает со всеми правами хоста. Принимать
  только разрешённые сертификаты (свой ключ), для чужих —
  подтверждение при первой установке.

## Ограничения манифеста
- Плагин не может добавить разрешения, роли, Activity, Service,
  виджеты. Хост объявляет заранее с запасом: `QUERY_ALL_PACKAGES`,
  контакты, интернет, роль ASSIST.
- Плагинам: API запроса разрешений,
  общий фоновый worker.

## Поиск (логика)
- Каждый провайдер в своей корутине, `flatMapLatest` на запрос,
  таймаут на провайдер, результаты потоком.
- Видимые элементы не переставлять, новые добавлять ниже.
- Ранжирование: score провайдера + frecency по истории запусков.
- Возможные точки расширения: `query.transform`, `providers`, `rank`,
  `group`, `item.actions`, `action.handle`, `key.enter`, `lifecycle`.
- `Item`: id, тип, title, score + расширяемые `extras`.

## Отброшенные варианты
- Дерево layout + свои токены + UI-кит + JSON-оверлеи в core:
  получается фреймворк поверх Compose, отклонено.
- Интерфейсы компонентов + делегирование `by` для частичной подмены:
  новый метод в интерфейсе ломает собранные плагины
  (AbstractMethodError) или обходит чужие переопределения через
  default-метод. Работу `by` с `@Composable` не проверял.
- Два APK (хост + продукт) — см. `self-modifying-apps.md`.
